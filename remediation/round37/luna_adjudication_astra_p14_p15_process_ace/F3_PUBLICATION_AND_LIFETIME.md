# F3 — Publication, admission, and retirement

This contract resolves commit points, P14 current-process matching, operational phase order, retirement, and failure behavior without changing E1 access or P14/P15 authority. It does **not** close delivery of the independent P15 creation expectation; that precise custody/resource decision is listed at the end. E1 remains a BA/SY administrative record and is never an A2/A3 admission oracle.

The P14/P15 expected creation IDs and seals remain BA-observed administrative G2 evidence. A2 does not read E1. P14 currentness can be checked by binding its contents to the actual connected PID and independently held process creation time; stale P14 does not match a different live incarnation. P15’s generation is an opaque lifecycle label, not a nonce, credential, independent case selector, or stand-alone proof of freshness. The six-field P15 record plus fixed case expectation prevents case switching, but does not independently prove that its observed file ID/generation is the current provisioner-approved one. No source may accept a P15 generation from A1/M4/M5 or a request.

## Publication commit points

**P15.** BA verifies the old P15 name is absent by handle-relative lookup, independently completes P11 expected rendering/readback, creates P15 with `FILE_CREATE`, writes the exact canonical bytes, flushes, reads them back twice from the same handle, checks exact identity/descriptor/parent/final path and content seal, then closes the writer handle. Only this complete sequence is a P15 publication. A collision is stale residue and fails the case setup; it is never opened as a substitute or overwritten. A failure attempts exact-handle cleanup; if cleanup/absence cannot be proved, the lifecycle stops and the next case cannot begin.

**P14.** BA starts and owns the startup observation session before A3 starts. A3 is not `SERVICE_RUNNING` or request-ready until its descriptor barrier, one first-instance creation/readback, and single startup event complete. BA validates the event, independently verifies process descriptor and P6/SCM/process facts, drains/seals ETW with zero loss, then creates P14 by `FILE_CREATE`, writes/flushes/readbacks exact bytes and descriptor on the same held object, records its exact creation identity/seal, and closes the writer handle. That close after successful readback is the publication commit point. Any collision, partial object, mismatch, or uncertain completion prevents admission; residue blocks future publication rather than being adopted.

For both resources, readers use share modes incompatible with a writer’s outstanding write handle. An absent record, an open-sharing conflict, a malformed record, a stale path occupant, or an unavailable BA publication prerequisite is `STOP_INCONCLUSIVE`; there is no alternate path, E1 lookup by C/B, response-derived repair, or retry.

## Admission and association

Admission is the already-required separately authorized comparison attempt after the BA provisioner’s P15 commit and BA collector’s P14 commit. It is not granted by the existence of a path alone. The controller’s fixed trusted case expectation is checked against P10, P15, the frozen P11 contract, and the exact response. A2 opens P14 only for the same attempt and authenticates the currently connected process directly. The connected pipe PID must match P14/SCM; the held process creation time must match P14 and the startup event; fixed image/service/pipe values must match P10/topology.

A2 and A3 are required to use the same P15 generation without exchanging authority over the pipe: they open the same fixed BA-owned object while O7’s single-case lifetime is active, compare the same six canonical fields against the same approved case/P10/P11 expectations, and retain their handles. P15 is not replaceable while either retained handle exists. A3 checks the P15 selection before P11 access; the request has no case field and cannot change it. The independent expected file identity/seal/generation for that same object is the unresolved F3 delivery item below. The next case cannot begin until the old service/process and all owned A2/A3 P15/P11/P14/pipe handles have closed and the exact old objects have been retired.

There is no second “admission bit” selected by this adjudication. The BA-created protected files, O7-controlled phase, and create-only/no-adoption sequence establish the operational commit, but do not deliver an independent expected P15 creation ID/generation to A2/A3. Until an approved delivery/custody source is named, a protected P15 reader must return `STOP_INCONCLUSIVE` when the current selection identity is not independently supplied. If the fixed object is ambiguous, unexpectedly present, or cannot be matched to a trusted phase expectation, the result is `STOP_INCONCLUSIVE`.

## Invalidation and observable failure

The collector’s lifetime ends after publication and its E1 bookkeeping; it need not survive as a monitor. ETW is a one-shot startup observation, not a heartbeat. Since E1 is not consumer-visible, runtime invalidation is enforced by the service/process/pipe source and attempt handles:

- A3 retains the original first-instance server handle for the process lifetime and never replaces it. Unexpected loss, error, or inability to retain it is fatal; close/disconnect the endpoint and stop the service.
- On SCM stop, A3 enters `STOP_PENDING`, rejects new requests, aborts any in-flight request, disconnects/closes the original server handle, and only then reports `SERVICE_STOPPED`. It does not send an error response that could be mistaken for a valid head.
- Process exit/signaling, pipe disconnect, PID change, failed live query, P14/P15 final-check drift, or lost required handle aborts the attempt. A2 discards any P11 bytes and returns typed incomplete evidence/no comparison input.
- Before the active-to-terminal transition, the commissioning controller closes admission, waits for the authorized attempt to complete or abort, stops/exits the old A3 service process, closes its owned handles, verifies exact old IDs, invalidates/removes old P14/P15/P11 by exact identity, then publishes the terminal case. If any process/handle/identity state is uncertain, transition stops.

P14’s currentness is not inferred from its generation alone: a stale P14 cannot match the actual connected server PID plus creation time and held process. P15’s currentness is phase-bound: only the selected phase’s P10/case/P11 expectation is admissible; the opposite case fails exact comparison, and same-case re-commissioning is not allowed in this run. Any future separately approved re-commissioning requires a new authorized lifecycle and fresh records; it cannot reuse this P15 or P14.

The final A2 success check runs before returning any comparison input: same pipe server PID, process creation time/path and unsignaled handle; same retained P14/P15 identities and canonical bytes as the initial reads; one complete correlated response; no extra message; all handles still valid. This detects within-attempt drift but does not independently establish that the observed P15 identity/generation was the provisioner-approved current one. The transition barrier remains closed until the comparison attempt ends. No success is returned from an uncertain race or a partially completed observation.

## Unresolved operator/resource decision

O1–O7 establish the BA/SY role boundary, P14 and P15 roles, selected case order, and lifecycle exclusion. They do not specify how the exact current P15 file identity, canonical seal, generation, and linked P11 identity/seal are delivered as independent expected inputs to both A2 and A3. P15 cannot authenticate its own generation, and E1 remains unavailable to C/B. A2/A3 each reading the same pathname and obtaining the same current bytes is not a substitute for an independently approved creation expectation.

Before a **P15 protected reader** or endpoint admission source is implemented, the operator/architecture authority must either (a) name an already approved protected delivery/configuration source and its writer, owner, readers, binding, lifetime, and retirement behavior, or (b) authorize a new narrowly scoped lifecycle-admission resource with those properties. Do not add C access to E1, broaden service/token/process rights, trust an A3 response, or let a writer artifact choose the expectation. This decision does not block the pure syntax parser, which receives explicit expectation values and makes no provenance claim.
