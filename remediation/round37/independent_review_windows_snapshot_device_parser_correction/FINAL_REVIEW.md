# Independent differential review — Windows SnapshotSession correction

**Decision B — one bounded raw-buffer correction remains before the next G1 source-preparation increment.** The `FILE_ATTRIBUTE_DEVICE` and duplicate-entry findings from the prior review are closed in source and synthetic tests. The production raw parser is now exercised directly, but it can silently omit nonzero bytes after a final `NextEntryOffset == 0` record or inside an oversized, aligned inter-record gap. A reviewer-only synthetic probe reproduced both omissions with the actual parser. No native fixture or protected host resource was opened.

This is a source-completeness finding, not evidence that Windows has returned such a malformed page. It matters because a complete inventory is a prerequisite for any completed comparison verdict. `SystemNativeCalls::next_page()` passes its zero-initialized 65,536-byte buffer to this parser, and `GetFileInformationByHandleEx` supplies no returned byte count to distinguish written records from buffer tail. The current parser returns only the linked entries and does not reject nonzero unlinked data. An extra child encoded in that data could be omitted before comparison. See [RAW_PARSER_AND_DEVICE_VERIFICATION.md](RAW_PARSER_AND_DEVICE_VERIFICATION.md).

The smallest correction is to reject nonzero bytes in each gap between the end of a record name and its nonzero next offset, and after a final zero offset through the supplied buffer. The rejection must be typed as incomplete observation, with `snapshot_complete=false`; focused direct-parser and integrated comparison tests should cover both cases. No different authority or opening model is needed. See [NEXT_G1_SOURCE_STEP.md](NEXT_G1_SOURCE_STEP.md).

The independent MSVC x64 and MinGW-w64 x64 rebuilds both exited 0 and reran the reported **2,872 synthetic assertions**. All 42 correction-manifest SHA-256 rows matched, and the accepted 133-check pure executables reran successfully. These results verify buildability and the exercised synthetic cases; they do not close the omission or establish native filesystem behavior. See [BUILD_AND_PROVENANCE.md](BUILD_AND_PROVENANCE.md) and [FINDING_CLOSURE.md](FINDING_CLOSURE.md).

No source, prior review, historical evidence, frozen test, runbook, checklist, or production S1 file was changed for this review. G1 remains unapproved. This decision does not imply Stage A, S1, or Round 3.7 acceptance.
