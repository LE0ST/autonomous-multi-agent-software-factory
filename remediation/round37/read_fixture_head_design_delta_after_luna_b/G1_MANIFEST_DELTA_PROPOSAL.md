## P14/P15 canonical schemas

P14 exact JSON field order/content is defined in [ENDPOINT_EVIDENCE_CONTRACT.md](ENDPOINT_EVIDENCE_CONTRACT.md). P15 is one compact UTF-8 JSON object, no BOM/LF/whitespace/unknown/duplicate keys, exact order:

```text
{"schema_version":1,"run_id":"<P10 run_id>","p10_sha256":"<64 lowercase hex>","selected_case_id":"spent-budget-active|spent-budget-terminal","selected_p11_sha256":"<64 lowercase hex>","selection_generation":"<32 lowercase hex>"}
```

The bar expression describes two separate permitted records; each concrete record contains exactly one case ID. The P11 seal is independently produced by case-specific P11 CREATE_NEW/readback. P15's protected BA origin and file descriptor are the trust anchor; neither case choice nor seal is accepted from A1/M4/M5 or IPC. The pure codec source slice receives a validated expected binding as an explicit value and does not read P14/P15.
