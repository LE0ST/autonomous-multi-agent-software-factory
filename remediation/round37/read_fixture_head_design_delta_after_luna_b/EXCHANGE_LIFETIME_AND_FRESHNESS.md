# ReadFixtureHead exchange lifetime and freshness

## Authority and nonce

For each separately authorized comparison invocation, A2 calls `BCryptGenRandom(nullptr, buffer, 16, BCRYPT_USE_SYSTEM_PREFERRED_RNG)` exactly once before opening the pipe. The result is 16 raw bytes; there is no text encoding, terminator, sentinel or rejection of zero-valued bytes. A failure yields typed A2 incomplete evidence at `generate-readfixturehead-nonce`, sends no request and performs no retry or fallback. No environment/config/M4/M5 or previous response can supply the value.

The nonce is fresh in the Stage A sense: generated by A2's OS CSPRNG anew for every authorized invocation and echoed by the one authenticated response. It is not a durable globally unique sequence and no durable replay database is required. Stage A makes no timestamp/window, cross-restart replay, persistent request-table or crash-recovery guarantee. CSPRNG collision probability is not converted into a persistent uniqueness database requirement.

The outstanding-request tuple in A2 memory is `(nonce[16], P10_SHA256[32], operation=1, selected_case expectation from protected P15)`. Exactly one tuple may be outstanding. The response must echo nonce and P10 binding byte-for-byte and carry operation 1. A2 compares these values and exact case-specific P11 payload before constructing any successful result. No nonce from the server is authoritative; the server only echoes. The request's P10 digest is a fixed binding assertion; A3 compares it to its independently loaded P10 and P15 values and never adopts it as authority.

## Connection and request sequence

One authorized attempt has this exact order:

1. A2 obtains its accepted current-process C TokenUser SID and validates P10/P15 and their trusted file bindings.
2. A2 generates the nonce. Failure stops before pipe open.
3. A2 loads/validates P14 and opens one client connection to the one fixed pipe name. It sets message-read mode, calls `GetNamedPipeServerProcessId` on that connected handle, opens only that PID with `PROCESS_QUERY_LIMITED_INFORMATION|SYNCHRONIZE`, compares live process creation time/path and endpoint evidence, and holds the pipe/process/P14 handles.
4. A2 writes exactly one 64-byte request as one native message. Short write, error, or disconnect closes the connection; no resend.
5. A3 reads exactly one complete native message. Before protected P11 access it validates exact wire shape, gets `GetNamedPipeClientProcessId`, impersonates that client, captures the actual thread token/TokenUser and required token context, compares C and fixed P10/P15, then calls `RevertToSelf`. Revert failure is process-fatal and causes no later protected I/O or normal error reply.
6. A3 performs one read through its fixed P11 custody reader under B and its preconfigured selected case. It does not take case/path/hash from request bytes.
7. A3 writes exactly one correlated success or generic `READ_INCOMPLETE` response message; no retry. It disconnects this client connection after the response/error and retains its original first-instance server handle for the service lifetime.
8. A2 reads exactly one bounded response message, verifies exact envelope, nonce, P10 binding, status, case-specific length and exact canonical P11 bytes, checks no extra response bytes already queued, then closes/discards the client connection. The process handle must remain live through acceptance. Any failure closes handles and returns typed incomplete evidence/no comparison input.

One retained server instance can serve sequential authorized attempts, but each attempt uses a new one-request client connection. Server instance, connection, logical request and authorized comparison attempt remain separate lifetimes.

## One-request enforcement and extras

- A2 source sends once. The composition path is invoked only by the separately authorized control path; M4/M5 never triggers it. A later attempt requires a new authorized control and new connection/nonce.
- A3 processes no second request on a connection. It checks for queued additional request bytes before P11 access; if present, it rejects the attempt and performs no P11 read. It never loops back to the request parser after accepting one request. It closes/disconnects after the sole response.
- A2 accepts at most one response. It rejects any extra bytes visible before response acceptance and closes immediately after one response. A second response is never decoded into another result.
- A partial/malformed exchange, wrong nonce, stale response, wrong connection, duplicate/unsolicited message or disconnect is terminal for this attempt. It produces no successful `BoundComparisonInput`. Connection closure is cleanup, not retry.
- A2 never reconnects within the same authorized attempt. Broker restart, lost first-instance handle or process identity change invalidates the attempt and P14; a future operation requires a separately authorized attempt after a separately approved lifecycle.

## Explicit nonrequirements and selected protections

| Mechanism | Stage A disposition | Reason/boundary |
|---|---|---|
| TLS | Not required or introduced | The accepted transport is one local message-mode named pipe with separately checked local peer/process identity. No network transport is added. |
| Per-message HMAC or signature | Not required or introduced | Request/response integrity and peer identity are supplied by the fixed local pipe and endpoint checks; the nonce is correlation, not a MAC key or identity proof. |
| Cryptographic challenge-response | Not required | A3 echoes the request nonce; echo alone is not authentication and does not replace A2's pre-send endpoint verification or A3's per-request client-token check. |
| Unpredictable nonce | Selected for this design | O6 selects an OS CSPRNG source; the pure codec accepts the 16-byte value but does not generate or attest it. |
| Durable nonce/request-ID replay table | Not required | One outstanding request, one connection, and a fresh per-invocation nonce suffice for this bounded Stage A exchange. Stage B replay/crash recovery remains deferred. |
| Timestamp freshness window | Not required | The protocol does not compare wall-clock time to accept a response. FILETIME fields in P14 are evidence metadata, not wire freshness windows. |
| Automatic broker restart | Prohibited for this lifecycle | Process/first-instance loss invalidates the exchange and endpoint generation. Any new incarnation needs separately authorized lifecycle approval and fresh evidence. |
| Finite end-to-end timeout | Not specified by the accepted Stage A design or O1–O7 | A later transport source design must document its bounded native waits/error behavior, but this delta does not invent a duration or turn timeout into retry. |
| New administrator IPC endpoint | Not required or introduced | BA receives startup evidence through the protected ETW collector path and writes P14; this is not an A2-callable administrator endpoint. |

The fixed message framing and exact parsing requirements are in [READ_FIXTURE_HEAD_WIRE_CONTRACT.md](READ_FIXTURE_HEAD_WIRE_CONTRACT.md). Detailed native errors remain local protected evidence; the wire error is intentionally generic.
