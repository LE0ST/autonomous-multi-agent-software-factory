# Proposed protected endpoint-evidence contract

**Status:** design only. No P14/P15 object, collector, ETW session, service, process, pipe or ACL was created or observed. This contract supplies a future trusted-input boundary; it does not claim G2 provenance exists.

## 1. Separation of inputs

- **P10** remains the canonical, immutable, pre-start assignment. It carries only already accepted static expectations, including P6/P7/P8/P9 hashes, created W/C/B SIDs, exact service/image/pipe names, fixed assignment and both frozen case maps. P10 is sealed before either service starts. It contains no measured runtime PID, process creation time, actual process TokenUser, actual pipe descriptor, or first-instance result.
- **P14** is the live endpoint-evidence object described below. It contains no `case_id`, P11 digest, operation, nonce, request ID, retry instruction, path selector, credential or authority update. It cannot select the case or cause an IPC operation.
- **P15** is a separate one-lifecycle selected-case record described below. It carries only the provisioner/operator-approved selection already required by `ApprovedAuthorityBinding`; it is not endpoint evidence and is never populated from an A2 request.
- **E1** remains BA/SY-only. Neither P14 nor this delta makes E1 readable by C/B.

## 2. P14 resource and exact access

Proposed row: `P14 = C:\S1PF_260926_A\config\endpoint-evidence.json`, one file under verified P3. BA holds the verified P3 directory handle and creates the one child relative to it using `NtCreateFile`, `OBJ_CASE_INSENSITIVE|OBJ_DONT_REPARSE`, desired access `FILE_READ_DATA|FILE_WRITE_DATA|FILE_READ_ATTRIBUTES|READ_CONTROL|SYNCHRONIZE`, share `FILE_SHARE_READ`, disposition `FILE_CREATE`, and options `FILE_NON_DIRECTORY_FILE|FILE_SYNCHRONOUS_IO_NONALERT`. It supplies the protected security descriptor at creation, does not inherit a handle, writes once, flushes, reads back through the same handle, and performs no update-in-place. The collector process is the designated BA identity; object owner/group are BA. Exact protected DACL:

```text
O:BAG:BAD:P(A;;FA;;;SY)(A;;FA;;;BA)(A;;0x00120081;;;C)
```

`0x00120081` grants C `FILE_READ_DATA | FILE_READ_ATTRIBUTES | READ_CONTROL | SYNCHRONIZE` only. `READ_CONTROL` is limited to this new P14 object so A2 can verify the owner/group/full DACL and protection before trusting the record; it grants no write, delete, or owner/ACL right. W and B have no ACE. The parent P3 remains as already designed. The collector records and independently reads back P14's file ID, parent ID, final path, owner/group/full DACL, DACL protection, bytes and SHA-256 before the record is made available to A2. A2 opens the fixed child relative to its already verified P3 handle with `OBJ_CASE_INSENSITIVE|OBJ_DONT_REPARSE`, desired access `FILE_READ_DATA|FILE_READ_ATTRIBUTES|READ_CONTROL|SYNCHRONIZE`, share `FILE_SHARE_READ`, disposition `FILE_OPEN`, and options `FILE_NON_DIRECTORY_FILE|FILE_SYNCHRONOUS_IO_NONALERT|FILE_OPEN_REPARSE_POINT`; it rejects a reparse object and retains the held handle through its one exchange.

One P14 file exists per broker/case lifecycle. It is created only after the endpoint collector verifies the live endpoint. Any loss detected before publication prevents P14 creation. After publication, process exit, service stop, first-instance-handle loss, or endpoint mismatch logically invalidates that exact P14 file ID in protected E1 state; the collector never republishes or reuses that generation. The ETW session is stopped after startup evidence is sealed, so ETW loss is a pre-publication failure, not a post-publication monitor. A2 also fails closed if the pipe connection, process handle or PID/start-time comparison ceases to match. Physical removal/quarantine occurs only after any A2-held P14 handle is closed and under separate G2/G5 authorization. No automatic restart can reuse a P14. If the collector cannot establish or maintain the evidence, no P14 is published; missing, unreadable, malformed, stale or mismatched evidence is `STOP_INCONCLUSIVE`.

## 3. Observer, APIs and binding

### BA collector observations

The approved BA collector is the only P14 writer. Before broker start it calls `StartTraceW` for a private `EVENT_TRACE_REAL_TIME_MODE` session, enables only the fixed provider with `EnableTraceEx2`, opens that session with `OpenTraceW(PROCESS_TRACE_MODE_REAL_TIME|PROCESS_TRACE_MODE_EVENT_RECORD)`, and consumes `EVENT_RECORD`s with `ProcessTrace`. It queries the session with `ControlTraceW`; any nonzero `EventsLost` or buffer loss is a hard failure. The collector stops the session with `ControlTraceW` after the evidence generation is sealed. It obtains:

1. **SCM registration/state/account:** `OpenSCManagerW(SC_MANAGER_CONNECT)`, `OpenServiceW` with `SERVICE_QUERY_CONFIG | SERVICE_QUERY_STATUS | READ_CONTROL`, `QueryServiceConfigW`, `QueryServiceStatusEx`, `QueryServiceObjectSecurity`, and `LookupAccountNameW` for the configured service account. It requires the exact protected service name, own-process type, demand start, exact P6 command line, B account SID, `SERVICE_SID_TYPE_NONE`, expected service DACL/owner/group from G2, `SERVICE_RUNNING`, and PID equal to the ETW process ID. The service DACL already gives BA full control; no C service right is added.
2. **Process lifetime/path and descriptor:** `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE | READ_CONTROL)` for the SCM PID, `GetProcessTimes`, `QueryFullProcessImageNameW`, and `GetSecurityInfo` for process owner/group/DACL. BA already has full access under the accepted process/service administration boundary; this does not add a C right. The collector holds the process handle for the evidence lifetime and signals invalidation when the process exits. It never enables `SeDebugPrivilege`; any access failure stops evidence creation. A2 separately opens the connected PID with only `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE` and uses only `GetProcessTimes`, `QueryFullProcessImageNameW`, and `WaitForSingleObject` on that handle.
3. **Image file:** open the exact protected P6 file under BA, bind to the recorded P6 volume/file ID/final path, read/hash the complete file, and compare with the independent G2 P6 seal and P10 static expected hash. The hash is of the protected file whose path is returned for the service process; the source/build review must establish the service image binding. C receives no P6 read ACE.
4. **Pipe creation/readback:** the pinned A3 source makes exactly one fixed `CreateNamedPipeW` call with the already accepted name, `PIPE_ACCESS_DUPLEX|FILE_FLAG_FIRST_PIPE_INSTANCE`, one instance, `PIPE_TYPE_MESSAGE|PIPE_READMODE_MESSAGE|PIPE_WAIT|PIPE_REJECT_REMOTE_CLIENTS`, fixed 4096-byte buffers and resolved descriptor. It emits one ETW event only after API success, `GetSecurityInfo` on the returned retained server handle, successful descriptor normalization, and current-process TokenUser query. The event is provider `{7C3A2609-CC37-4E9A-8C92-4F52B7B31D37}`, event ID 1/version 1, with ETW header PID/time and exact payload: `status:u32LE=0`, `dwOpenMode:u32LE=0x00080003`, `dwPipeMode:u32LE=0x0000000E`, `nMaxInstances:u32LE=1`, `nOutBufferSize:u32LE=4096`, `nInBufferSize:u32LE=4096`, `server_handle_value:u64LE` (diagnostic only), `token_user_sid_length:u8`, `token_user_sid` (binary SID, 8..68 bytes), `security_descriptor_length:u16LE`, `security_descriptor` (self-relative bytes, 1..4096 bytes). The total event payload is at most 4199 bytes and has no trailing data. The BA collector validates the ETW header PID against SCM PID and the collector-measured process creation time, and records the collector's `GetSystemTimeAsFileTime` value immediately after accepting the event. It converts the descriptor to canonical SDDL and compares its owner/group/full protected DACL to the approved resolved descriptor. A missing, duplicate, failed, malformed, lost or mismatched ETW event prevents P14 publication. Events from other PIDs are not evidence. ETW header time is retained only as an opaque diagnostic timestamp; it is not interpreted as FILETIME.
5. **Actual B TokenUser:** the pinned A3 process queries its own current process token using `OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY)` and `GetTokenInformation(TokenUser)`, converts the SID canonically, and emits it in the same startup ETW event. The collector checks the ETW event is from the verified P6 PID/incarnation and compares the value to the independently approved B SID and SCM account SID. This is an out-of-band, source-pinned startup observation captured by the BA collector; it is not a `ReadFixtureHead` response and cannot bootstrap an A2 request. The P6 source contract must fail service startup if this query/emit fails. The collector does not open B's token and does not enable debug privilege.
6. **First-instance/retained-handle provenance:** the exact reviewed P6 source must call the first-instance API once, report SCM `SERVICE_RUNNING` only after the success/readback event, retain that returned handle for the service lifetime, never create a replacement instance in-process, and stop the service if the handle is lost. P14 records `first_instance_create_succeeded=true` and `first_instance_collector_observed_filetime`, the collector's `GetSystemTimeAsFileTime` value recorded immediately after accepting the one startup event. The source hash and startup sequence are part of the G1 review; the collector rejects any event not from that exact hash. A2 directly matches its connected server PID and process creation time to P14 and holds the process handle. Because automatic restart is not selected, a lost server breaks the connection; any later service incarnation requires a separately authorized lifecycle and new P14.

### Minimal direct A2 process-object right

The connected-handle API supplies a PID. Comparing only that number to an immutable file does not bind the live pipe to a process incarnation after PID reuse. A2 therefore performs `GetProcessTimes` and `QueryFullProcessImageNameW` on the exact process identified by the connected-handle PID. Required process handle access is only `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE` (`0x00101000`); A2 retains that handle through response validation and verifies the process remains unsignaled. No `PROCESS_VM_READ`, `PROCESS_DUP_HANDLE`, `PROCESS_QUERY_INFORMATION`, token access, service access, or debug privilege is requested by A2. Token DACLs remain independent; P14 carries the collector-validated B TokenUser.

This requires one explicit new process-object DACL ACE for the created C SID on the B broker process. It is the only new direct C query right proposed by this delta. Proposed protected process DACL is `O:<B>G:<B>D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;GA;;;<B>)(A;;0x00101000;;;<C>)`; the only new ACE is C's `0x00101000` allow. The exact process owner/group/DACL before and after must be captured; no other ACE or right may change. The A3 process must install and read back that ACE before creating the pipe. Failure is fatal before service `RUNNING`. This is a proposed versioned topology/G1 manifest delta, not an assumed current permission. Independent review must verify the API access mask and actual process DACL implementation. A2 does not call `OpenProcessToken`; the new process ACE does not alter the token object's DACL, and G2 must verify the token DACL grants C no query access. If the process query right plus the actual token DACL nevertheless permits C to obtain B token information, the topology delta is not acceptable and must return to review. No service/file/token/pipe ACL is broadened.

### Endpoint-to-connection comparison

For every A2 connection, A2:

1. reads and validates P14 from its fixed protected P3 child;
2. opens the one fixed pipe name for the authorized attempt and sets message-read mode;
3. calls `GetNamedPipeServerProcessId` on that actual connected handle;
4. opens only that PID with `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE`, reads current creation time and image path, and compares PID, creation time, path and process-liveness to P14; A2 does not request `READ_CONTROL` or token access;
5. compares P14's P10 digest, P6 hash/path, B SID, service name/account/state, pipe name/settings/descriptor and first-instance fields to independently approved static values and this run's G2 records;
6. retains both the connected pipe and process handles through the one request/response; any disconnect, process signal, mismatch or evidence invalidation stops the attempt and yields no comparison input.

The file's immutable generation is tied to one observed server process start and one retained first-instance handle. P14 never authorizes the operation or selected case. A2 does not infer identity from the response.

## 4. Canonical P14 content

P14 is UTF-8 without BOM, one compact JSON object, no trailing LF, exact property order below, no duplicate/unknown properties, no whitespace outside strings, no escapes other than `\\` and `\"`, ASCII-only values, canonical decimal integers (no sign/leading zero except `0`), lowercase hex, and JSON booleans. Maximum length is **2048 bytes**. The record must contain exactly:

```text
{"schema_version":1,"run_id":"<P10 run_id>","p10_sha256":"<64 lowercase hex>","endpoint_generation":"<32 lowercase hex>","observed_filetime":"<16 lowercase hex>","server_pid":<1..4294967295 decimal>,"process_start_filetime":"<16 lowercase hex>","process_owner_sid":"<G2-recorded canonical process owner SID>","process_group_sid":"<G2-recorded canonical process group SID>","process_dacl_sddl":"<canonical resolved process SDDL>","service_name":"S1PF_Broker_260926_A","service_type":16,"service_start_type":3,"service_binary_path":"\"C:\\S1PF_260926_A\\bin\\broker.exe\" --service --binding \"C:\\S1PF_260926_A\\config\\binding.json\"","service_account_sid":"<canonical B SID>","service_state":"RUNNING","service_owner_sid":"<G2-recorded canonical service owner SID>","service_group_sid":"<G2-recorded canonical service group SID>","service_dacl_sddl":"D:P(A;;GA;;;SY)(A;;GA;;;BA)","token_user_sid":"<canonical B SID>","image_path":"C:\\S1PF_260926_A\\bin\\broker.exe","image_volume_serial":"<16 lowercase hex>","image_file_id":"<32 lowercase hex>","image_sha256":"<64 lowercase hex>","pipe_name":"\\\\.\\pipe\\S1PF-broker-260926-A","pipe_open_mode":"00080003","pipe_mode":"0000000e","pipe_max_instances":1,"pipe_out_buffer":4096,"pipe_in_buffer":4096,"pipe_owner_sid":"<G2-recorded canonical pipe owner SID>","pipe_group_sid":"<G2-recorded canonical pipe group SID>","pipe_dacl_sddl":"<canonical resolved SDDL>","first_instance_create_succeeded":true,"first_instance_collector_observed_filetime":"<16 lowercase hex>"}
```

Angle-bracket values above are format descriptions, not literal accepted values. The concrete G2 record substitutes actual independently created SIDs, IDs and hashes. All path/name values are compared to exact P10/topology constants using accepted Windows path comparison; no field is a selector. `pipe_open_mode` and `pipe_mode` are exactly eight lowercase hex digits for the numeric values stated above. `endpoint_generation` is a 16-byte BA collector CSPRNG value rendered as 32 lowercase hex and recorded in the G2 ledger. `observed_filetime` is captured by the collector with `GetSystemTimeAsFileTime` immediately before P14 creation. `first_instance_collector_observed_filetime` is captured with the same API immediately after validating the sole startup event; the ETW header timestamp is retained only as opaque diagnostic evidence, not interpreted as FILETIME. Neither grants case or operation authority. The wire request carries only the P10 binding digest and nonce, never this record or its generation.

P14 validation rejects any length over 2048, malformed UTF-8/ASCII, wrong property order, duplicate/unknown/missing field, noncanonical number/hex/SID, inconsistent SID/account, wrong P10 digest/run, image or service mismatch, wrong pipe mode/descriptor, false first-instance field, bad file/parent identity, or stale process/start identity. `endpoint_generation` is an opaque BA-created identifier checked for its exact 16-byte lowercase-hex form and bound to the protected P14 file identity; A2 does not claim to detect reuse by consulting a durable replay database. `observed_filetime` and `first_instance_collector_observed_filetime` are 64-bit Windows FILETIME values rendered as 16 lowercase hex digits. The collector obtains a fresh endpoint generation with `BCryptGenRandom`; failure means no P14. There is no fallback to E1 or P10 for missing live evidence.

## 5. Failure and invalidation rules

- Collector cannot start/maintain ETW through startup-event acceptance, observes any lost events before sealing that evidence, cannot query SCM/process/image, cannot validate actual B TokenUser, descriptor or first-instance source, or sees a mismatch: **do not create P14; stop before A2 sends**.
- P14 absent, stale, malformed, inaccessible, from a prior endpoint generation, or not bound to the connected PID and process creation time: close handles; return typed incomplete A2 endpoint evidence; no request is sent and no comparison input is produced.
- Broker process exits or A3 loses its original pipe handle: the connection fails; A2 closes it and reports incomplete. The current P14 file ID is logically invalidated in protected E1 state. No automatic restart or reuse is permitted.
- A separately authorized new broker incarnation starts only after the old service/pipe lifetime is stopped, old P14 is invalidated, and G2 creates/readbacks a new endpoint generation. It gets a new PID/start observation and P14. PID equality alone never revalidates stale evidence.
- Missing/malformed P14 never authorizes a lookup in E1, P12, a writer result, environment variable, service response, or alternate path.

## 6. Proposed resource/lifecycle row

P14 is one protected read-only-to-C evidence object in P3, created by BA collector after service start and before any A2 request. Invalidation is logical immediately on process/first-instance/service loss: the collector records the invalidation against P14's file ID in E1 and never republishes or reuses that generation. Physical remove/quarantine occurs only after outstanding A2 handles close and under separate G2/G5 authorization, then exact-ID verification precedes any new P14 creation. G2 records P14's creation file ID, parent ID, descriptor, hash, ETW session/provider identity, verified SCM/process/token/image/pipe fields, and the raw observation receipt in E1. The corresponding G1 manifest row must bind the collector and broker source/build hashes, ETW provider GUID/event schema, process-object DACL delta, exact P14 schema, failure behavior and G5 reverse dependency. No resource is created by this design task.
