# Next bounded G1 source step

## Disposition: pure source slice ready

L2 and L3 now specify one exact codec and one exact correlation behavior. The approved next increment is limited to a **pure `ReadFixtureHead` request/response codec plus per-invocation correlation validator**. It performs no pipe operation, token/process/service query, protected open, ETW operation, P14/P15 read, G2/G3 action, or host operation.

The future source accepts bounded byte arrays and explicit trusted expected inputs:

- expected P10 SHA-256 (32 bytes);
- expected selected-case canonical P11 bytes/hash/length (from an already validated case binding);
- one 16-byte nonce generated by the A2 transport caller for this invocation.

It encodes the exact 64-byte request; decodes only 66-byte error or 365/366-byte success responses; validates magic/version/kind/operation/status/total length/payload length, exact nonce echo and P10 binding echo; and compares the success P11 payload byte-for-byte with the explicit expected canonical bytes. It returns typed decode/correlation success or typed incomplete failure only. It never generates the nonce, opens a pipe, chooses a case, loads configuration, hashes received bytes to create an expectation, or claims endpoint identity.

## Claims excluded from this slice

The codec does not claim native peer authentication, trusted bootstrap provenance, live A2/A3 identity, P14/P15 validity, P11 filesystem custody, case commissioning, first-instance continuity, process lifetime, no actual retry, G1 approval, or Stage A/S1 success. Those require separate source review and later authorized host evidence. The P14/process-object rights proposals in the manifest are design only and are not implemented by the codec.

## Independent source review requirements

Review the codec against [READ_FIXTURE_HEAD_WIRE_CONTRACT.md](READ_FIXTURE_HEAD_WIRE_CONTRACT.md) and [EXCHANGE_LIFETIME_AND_FRESHNESS.md](EXCHANGE_LIFETIME_AND_FRESHNESS.md). Require independent literal active and terminal success vectors, the exact error vector, malformed/offset mutation vectors, all exact maxima, no allocation before length validation, no trailing/extra acceptance, exact echo comparison, standard/non-standard exception handling if applicable, and production/test seam separation. The test oracle must not generate expected bytes by calling the codec under test. Source hashes and all build evidence must be placed in a new isolated package; this design writes no code or test artifacts.

G1 remains HOLD / UNAPPROVED; S1 remains OPEN; Stage A and Round 3.7 remain NOT PASSED. This Decision A authorizes only the bounded pure source increment and nothing on the Windows host.
