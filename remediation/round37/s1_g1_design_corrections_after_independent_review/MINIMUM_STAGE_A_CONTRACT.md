# Minimum disposable Stage A fixture — proposed G1 correction

**Status:** design only; no fixture source or resource exists by this document. The original [frozen S1 cases](../../../tests/security_acceptance/round37/test_s1_durable_authority.py), corrected [runbook](../s1_windows_preflight_runbook/PREFLIGHT_RUNBOOK.md) and [Stage A/B boundary](../s1_windows_preflight_runbook/STAGE_A_STAGE_B_BOUNDARY.md) retain their criteria. A fixture-specific demonstration must not be labeled a pass of the installed Python test or of production S1.

## Exact fixture behavior

Stage A uses distinct genuine A1, A2 and A3 Windows processes and actual tokens. A2 is an SCM service under C; it launches A1 with `LogonUserW(LOGON32_LOGON_BATCH)` and `CreateProcessAsUserW` using the protected exact image/argv/working directory, sanitized environment, `bInheritHandles=FALSE`, and no inherited standard/privileged handle. A3 is an SCM service under B. It owns the exact first-instance, one-instance pipe and authenticates the peer token on each complete request. The pipe client proves the connected server before sending. A3 performs protected I/O only after successful `RevertToSelf` as B. A1 can write, restore, rename, replace, lock and delete the full disposable mutable set M1–M5.

P11 is a protected **fixture marker/head**, not a database: one reviewed, provisioner-created canonical record containing a manifest-fixed run marker, rendered P10 assignment digest, fixture case identifier, expected latest mutable-pair digest and a small display tuple (`generation`, `worker_runs`, `terminal`). The marker and field schema are fixed at G1; the rendered P10 digest is recorded at G2 after created SIDs are known. P12 is a separately protected copy/control target with an explicit identity and hash; it is not recovery authority. Both are B-readable/writable for authorized positive controls and inaccessible to A1/C. There is no registry, log, operation table, reservation or transaction engine. A3's interface has only `Identity`, `ReadFixtureHead` and fixed G3-authorized `WriteControlP12` to prove B's protected write/read access. That control writes one manifest-fixed P12 byte sequence and verifies it; it accepts no writer-derived path, task or state transition and never changes P11. Its request bytes and intended before/after P12 values are frozen in the G3 manifest. No reset, repair, enrollment, admin or arbitrary file API exists.

For each paired case, the G1 manifest fixes an **old complete mutable snapshot/witness/lock set** and a **latest complete set** with distinct hashes, plus the exact expected P11 latest digest and display tuple. These are disposable fixture bytes in one dedicated declared state directory under M2. Every state-principal-writable file in that directory, including lock/witness/key if present, belongs to the complete set; M4 result and M5 effect are outside that state directory and have separate evidence roles. The later one-row-per-object manifest must name every file and the directory itself. Under actual A1, writing the latest set and saving/restoring the old set are positive mutable controls; those operations use their separate reviewed mutable-operation access/share rows outside the fresh-controller comparison.

For the fresh A2 comparison, first hold the verified ancestor chain, then open the state directory with `NtCreateFile`: desired access exactly `FILE_LIST_DIRECTORY|FILE_READ_ATTRIBUTES|READ_CONTROL|SYNCHRONIZE`, share exactly `FILE_SHARE_READ`, disposition `FILE_OPEN`, options exactly `FILE_DIRECTORY_FILE|FILE_OPEN_REPARSE_POINT|FILE_OPEN_FOR_BACKUP_INTENT|FILE_SYNCHRONOUS_IO_NONALERT`, and `OBJ_CASE_INSENSITIVE|OBJ_DONT_REPARSE` on a single component relative to its held parent. Open every listed present regular state child relative to that held directory with desired access exactly `FILE_READ_DATA|FILE_READ_ATTRIBUTES|READ_CONTROL|SYNCHRONIZE`, share exactly `FILE_SHARE_READ`, disposition `FILE_OPEN`, options exactly `FILE_NON_DIRECTORY_FILE|FILE_OPEN_REPARSE_POINT|FILE_SYNCHRONOUS_IO_NONALERT`, and the same object-attribute flags. Both opens omit `FILE_SHARE_WRITE` and `FILE_SHARE_DELETE`. The general protected-object identity/read walk follows its reviewed operation-specific access/share profile; its `FILE_SHARE_READ|FILE_SHARE_WRITE` default is never used for this complete state comparison. A2 reads P10 and a fresh A3 `ReadFixtureHead`, then establishes the complete held state-handle set before validating inventory and hashing. It holds the verified directory and every relevant child handle through inventory validation, reads/hashes through those handles, repeats the complete inventory and handle-identity check, and compares the exact digest and marker **before launching A1 or reading M4**. It never closes and reopens a child by an unchecked path between validation and use.

The inventory must be complete and match the G1 case manifest's exact child names/types, excluding only native `.` and `..` entries. The state directory must match its G2 identity; each mutable child's actual handle identity and parent binding must remain consistent from validation through final comparison, allowing A1's authorized pre-comparison replacement to change a child's original G2 file ID. Reparse, unlisted or changed objects, unexpected child types, identity drift and incomplete inventory are rejected. A sharing violation, conflicting existing writer/deleter handle, unopenable present child or inability to establish or retain any part of the complete profile produces a typed `STOP/INCONCLUSIVE` with native NTSTATUS/mapped Win32 error where present and the exact failed object, profile and step; it never accepts a pair on partial evidence. A complete observation of the old-pair mismatch or all-listed-children deletion is a defined comparison rejection after successful process/import/IPC reach, not a snapshot-establishment stop. It accepts the untampered latest set with the expected tuple. Deletion may not enroll empty state or manufacture a current pair. Missing A3, mismatched server/peer, missing P11, unknown identity, malformed pair or unavailable read is a typed stop, never success. The fresh process must have no cached prior head. The evidence records the actual token and broker read, parser outcome and immutable before/after marker/head. This preserves the **attack and rejection criteria** of the frozen paired cases without claiming production generation, spend or terminal semantics from fixture display values.

The eventual P/M manifest records exact access/share masks for the general P1–P13/E1 identity/read and allowed control rows, the state directory under M2 and every state-child snapshot row, and distinct A1 mutable-operation rows for M1–M5. Every fresh-controller per-attempt row for untampered latest, old-pair restore and complete deletion in both frozen cases records the directory/child access/share masks and options, handle lifetime, complete inventories, child identities/hashes, final consistency result and exact native failures; protected A1 probe and independent collector attempts record their own operation-specific flags. The requested share mask alone does not assert that Windows supplied stable bytes or a complete snapshot. Later G1 source review must verify the implementation's concurrency and handle behavior, and actual G3 evidence must establish stable inventory, content and identities under this profile.

The frozen case map remains explicit: in both **spent-budget active** and **terminal** fixtures, the latest state has `worker_runs=1` and `generation>0`; the terminal case reports `HALT_HUMAN` and `FAILED`, while the active case reports `INIT`. For each fixture, A1 restores every older colocated state file and a fresh controller rejects; A1 separately deletes every colocated state file and a fresh controller rejects. Untampered latest state reopens with its exact generation, spend and terminal status. The fixture rejection must be a defined comparison failure after successful process/import/IPC reach, not a process, permission or import error. The original Python `CorruptStateError` expectation remains frozen for installed Stage B acceptance; a C++ fixture comparison is separately labeled Stage A evidence.

The G3 sequence also includes A1 protected file, parent, service, process/token, credential and pipe attempts; A1-originated controller route attempts; authorized A2 pipe/assigned-job controls; and authorized B protected-file access. Each is a separate per-attempt record under the [file/probe contract](FILE_IDENTITY_AND_PROBE_CONTRACT.md). A1 direct pipe denial is established by actual connection/API and B-observed peer token if a connection exists. A1 service/process/credential reach is tested under its real token. A successful protected mutation is FAIL even when later reversed.

## Source responsibility limit

The eventual reviewed source may use fewer than six units. If those names are retained: `broker.cpp` owns SCM service dispatch, first-instance pipe, per-request peer inspection and only the marker/head controls; `controller.cpp` owns P10 binding, protected operator control, fixed A1 launch, strict M4 data parser and fresh comparison; `writer.cpp` owns mutable positive controls and frozen native negative attempts; `native_capture.cpp` owns token, ancestry, handle, endpoint and per-attempt native evidence; `provision.cpp` owns only approved create-only manifest rows and descriptor/identity readback; `policy_read.cpp` is a read-only preparation collector, not a runtime fixture. A source change adding state machinery or a new endpoint returns to independent G1 review.

Stage A may demonstrate **only** exact-build principal separation, peer authentication, protected marker/head custody, mutable writer control, fresh comparison rejection, native denials and authorized controls. Transaction ordering, durable latestness, budget monotonicity, permanent identity/tombstones, operation replay, reservations, lost-result uncertainty, crash or power-loss recovery, S4/S5, Git CAS, migration and production rollback/deletion resistance are `DEFERRED TO STAGE B`. Runbook rows that assume those functions, including two-controller contention, outage reservation, broker commit/restart and gate effects, are marked `DEFERRED TO STAGE B` where this fixture lacks the operation. The frozen paired rollback/deletion attack criteria remain mandatory for Stage A evidence and remain separately mandatory for installed Stage B acceptance.
