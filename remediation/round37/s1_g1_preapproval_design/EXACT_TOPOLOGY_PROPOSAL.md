# Exact protected-local topology proposal

**Engineering proposal, not an executable manifest or G1 approval.** Every name below is bound to candidate `LEO/260926_A`; an operator-selected change must be propagated to every row and rebuilt/reviewed. SIDs marked `W`, `C`, `B` below are symbolic placeholders for the **created** A1/A2/A3 SIDs, not guessed values. `BA=S-1-5-32-544`, `SY=S-1-5-18`. Actual tokens, effective rights and created IDs are **PENDING G2/G3**. The G1 source/build and one-row-per-object/right manifest are still missing.

For each account: exact SAM and `LookupAccountNameW` absence first; `NetUserAdd` must report success rather than existing-user adoption; then record `NetUserGetInfo`, created SID, enabled flag and group membership. Grant R1 `SeBatchLogonRight` to W, R2/R3 `SeServiceLogonRight` to C/B using `LsaAddAccountRights` after recording `LsaEnumerateAccountRights` for that created SID. No service/task/admin/backup/restore/debug/take-ownership right is proposed for W. Read-only policy collector specification: `LsaOpenPolicy(POLICY_LOOKUP_NAMES|POLICY_VIEW_LOCAL_INFORMATION)`, `LsaEnumerateAccountsWithUserRight` for `SeBatchLogonRight`, `SeDenyBatchLogonRight`, `SeServiceLogonRight`, `SeDenyServiceLogonRight`, plus effective local/domain policy source and account/group membership; record NTSTATUS and completeness. If policy denies required logons or cannot be resolved, stop before G2 logon/service start. No policy-wide allow/deny edit is proposed.

`CreateServiceW` uses `SERVICE_WIN32_OWN_PROCESS`, `SERVICE_DEMAND_START`, `SERVICE_ERROR_NORMAL`, exact account and protected image path, SCM-supplied password without command-line or transcript bytes. `ChangeServiceConfig2W(SERVICE_CONFIG_SERVICE_SID_INFO, SERVICE_SID_TYPE_NONE)` is selected: isolation is by the two distinct account SIDs, without an invented service SID grant. Apply an explicit protected service-object DACL with `SetServiceObjectSecurity(DACL_SECURITY_INFORMATION)` and verify with `QueryServiceObjectSecurity`: `D:P(A;;GA;;;SY)(A;;GA;;;BA)`. This DACL-only call does not set owner/group; record their actual values. No W, C or B ACE on either service object. `SetServiceStatus` and SCM dispatch remain the services' own control path. Verify the SCM manager descriptor and W's actual `SC_MANAGER_CREATE_SERVICE`/service-control rights at G2/G3. Do not change the pre-existing SCM manager DACL. Exact SCM image command lines are:

```text
"C:\S1PF_260926_A\bin\broker.exe" --service --binding "C:\S1PF_260926_A\config\binding.json"
"C:\S1PF_260926_A\bin\controller.exe" --service --binding "C:\S1PF_260926_A\config\binding.json" --credential "C:\S1PF_260926_A\config\writer.dpapi"
```

No automatic start/restart, scheduled task, interactive service or fallback launcher is selected. G2 may `StartServiceW` only under its separate identity-only authorization. Controller calls `CryptUnprotectData` on P13 in its own process, zeroes plaintext after use, then `LogonUserW(S1PF_W_260926_A, LEO, secret, LOGON32_LOGON_BATCH, LOGON32_PROVIDER_DEFAULT)` and requires a primary token with user SID W. It calls `CreateEnvironmentBlock(W-token, FALSE)`, removes secret-bearing and unreviewed variables, and `CreateProcessAsUserW` with exact protected `lpApplicationName=C:\S1PF_260926_A\bin\writer.exe`, literal command `"...\writer.exe" --task s1pf-task-260926-a-01 --result "G:\S1PF_260926_A\work\writer-result.json"`, `CREATE_UNICODE_ENVIRONMENT|CREATE_NO_WINDOW`, `bInheritHandles=FALSE`, `lpCurrentDirectory=G:\S1PF_260926_A\work`, `lpDesktop=NULL`, no standard-handle inheritance. It closes token/process handles and destroys the environment block. `SeIncreaseQuotaPrivilege` and possibly `SeAssignPrimaryTokenPrivilege` are dependency checks in the *actual A2 service token*; they are not granted by this design. If launch fails for lack of privilege or policy, G2 stops and returns to G1. The writer result file is untrusted input with a fixed length/schema limit; it cannot set a caller SID, role, namespace, path or broker verb. Controller binds its request to its protected P10 assignment, not values from M2.

## Protected file tree and descriptor classes

The observed `C:\` DACL contains inheritable Authenticated Users grants; `G:\` is broadly mutable. Create **new** children with explicit `SECURITY_ATTRIBUTES` (`bInheritHandle=FALSE`) and protected DACL `D:P` using `ConvertStringSecurityDescriptorToSecurityDescriptorW`, `CreateDirectoryW` or `CreateFileW(CREATE_NEW)`. Verify owner/group/DACL via `GetSecurityInfo` on the returned handle and reopen by handle/final path/file ID. Never use an inherited default DACL or modify either volume root. `FA` is restricted to SY/BA and the expressly named role; `RX=0x001200A9` is read/execute only; `M=0x001301BF` is disposable modify without `WRITE_DAC`/`WRITE_OWNER`. All templates are resolved to actual SIDs after account creation and independently checked before use.

Class shorthand expands exactly as follows: `DIR(S)` = `O:BAG:BAD:P(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)` plus `(A;OICI;<mask>;;;S)` for each listed role; `FILE(S)` is the same without `OICI`. P1 uses direct role ACEs; P2/P3/P4/P5 use `DIR`, files P6–P13 use `FILE`. Explicit `D:P` on each new file prevents the observed `C:\` Authenticated Users inheritable ACE from becoming a child write grant. For every parent and child, G2/G3 checks W's **actual** `FILE_ADD_FILE`, `FILE_ADD_SUBDIRECTORY`, `FILE_DELETE_CHILD`, `DELETE`, `WRITE_DAC`, `WRITE_OWNER`, replace/rename and reparse paths. A nonadmin W ability to delete or replace P1/E1 via `C:\`, or to mutate any protected child, is a stop condition; this proposal does not change `C:\` to solve it. Ownership, backup/restore/take-ownership privileges and enabled groups must be checked on the real W token.

## Pipe and authority contract

I1 is exactly `\\.\pipe\S1PF-broker-260926-A`, one 20-character component. A3 calls `CreateNamedPipeW(I1, PIPE_ACCESS_DUPLEX|FILE_FLAG_FIRST_PIPE_INSTANCE, PIPE_TYPE_MESSAGE|PIPE_READMODE_MESSAGE|PIPE_WAIT|PIPE_REJECT_REMOTE_CLIENTS, 1, 4096, 4096, 0, SECURITY_ATTRIBUTES)` with `bInheritHandle=FALSE` and resolved descriptor `O:<B>G:<B>D:P(A;;FA;;;<B>)(A;;0x00100183;;;<C>)(A;;RC;;;BA)`. C's mask includes read/write data, attributes and synchronize, **not** bit `0x4` (`FILE_CREATE_PIPE_INSTANCE`); no generic write ACE is used. W has no connect ACE. Only one server instance exists; an unexpected instance, `ERROR_ACCESS_DENIED`, other creation error or loss of the first handle stops pipe commissioning. The broker keeps that handle for its lifetime. See [pipe reconciliation](PIPE_CONTRACT_RECONCILIATION.md).

C opens the local pipe with `CreateFileW(FILE_READ_DATA|FILE_WRITE_DATA|FILE_READ_ATTRIBUTES|FILE_WRITE_ATTRIBUTES|SYNCHRONIZE, OPEN_EXISTING, SECURITY_SQOS_PRESENT|SECURITY_IDENTIFICATION)` and message read mode. Before sending even the inert G2 handshake it calls `GetNamedPipeServerProcessId` on the **connected handle** and checks PID, start time, image path/hash, SCM registration/account SID and recorded first-instance provenance. A mismatch closes the handle. B calls `GetNamedPipeClientProcessId`; after reading each message, it calls `ImpersonateNamedPipeClient`, `OpenThreadToken(TOKEN_QUERY)`, `GetTokenInformation` for user/groups/logon/integrity/impersonation level, compares the observed SID C and P10's fixed namespace/task binding, closes the token and calls `RevertToSelf` **before** protected I/O. Every failure denies and stops that request. Client-supplied SID/role/namespace fields are ignored. No live admin pipe endpoint is selected: an elevated provisioner writes P10 before service start; any assignment/config change is a new G1/G2 review. G2 permits only a nonmutating identity handshake; W's attempted pipe access and all authz/state probes require G3.

## Custody, build and cleanup contract

The operator supplies three disposable account secrets through an approved no-echo input channel to the elevated provisioner. No secret appears in argv, environment, JSON, evidence, source, repository or logs. The provisioner encrypts the W secret directly to P13; SCM receives C/B service secrets via `CreateServiceW` protected memory. Zero transient plaintext buffers and record only API status. The old CredMan K1 is deliberately removed; no `CredWriteW` or cross-account Credential Manager access is implied. E1 raw records are hashed into a canonical SHA-256 manifest; an approved independent destination receives a sealed copy and receipt before teardown. E1 retention owner and period are still undecided.

Required source set: `broker.cpp` (SCM dispatch, first-instance pipe, peer-token checks, one-file state and snapshot), `controller.cpp` (SCM dispatch, DPAPI read, batch launcher, bounded result parser), `writer.cpp` (inert G2 identity mode and exact G3 API calls), `native_capture.cpp` (same-PID token/handle/SCM/file/pipe capture and per-attempt raw codes), `provision.cpp` (create-only accounts/rights/ACL/SCM/DPAPI with provenance), `policy_read.cpp` (read-only LSA policy and exact display-name checks). Pin compiler/Windows SDK versions and compile each from reviewed source, for example `cl.exe /nologo /W4 /WX /O2 /DUNICODE /D_UNICODE /std:c++20 <source> /link advapi32.lib userenv.lib crypt32.lib`, adding only documented libraries per module. Record source revision, exact command, compiler/SDK hashes, all static/dynamic dependencies, PE SHA-256 and signatures. These files, binaries and hashes **do not yet exist**; the accepted observation helper supplies none of their peer-authentication or fixture implementation. Before signing G1, render a one-row-per-object/right table with exact creation/reverse arguments, inherited DLL/config inventory, and a frozen per-attempt target/API/desired mask/expected native result/before-after reader/positive-control list. Unknown or added artifacts return to G1.

G5 reverse order, only with separate approval: stop identified clients/services; close the recorded A3 pipe handle; compare service names, binary hashes/config/account/SIDs with G2 records before `DeleteService`; remove P13 only by file ID after A2 stops; remove only run-created R1–R3 with `LsaRemoveAccountRights`; remove P11/P12 and exact static files, then empty protected/mutable directories by recorded file/parent/volume IDs; finally `NetUserDel` for matching A1/A2/A3 SIDs. No prefix scan is deletion authority. Reparse, foreign content, changed ACL/ID/SCM config, uncertain pipe owner or missing sealed evidence stops the affected reverse action and preserves residue. E1 is retained pending its separate custody/retention decision. No action touches real Agentes state.
